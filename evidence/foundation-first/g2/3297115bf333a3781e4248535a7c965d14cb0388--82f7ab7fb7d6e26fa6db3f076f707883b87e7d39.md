- A permanent failure with a deliberate first DLQ outage leaves the source unacknowledged; a replacement listener in the same group redelivers it, then forwards it to the real raw DLQ path before acknowledgement.
- A malformed frozen frame reaches DLQ with its source key, complete Confluent frame, and ordered source headers byte-for-byte preserved; only the four canonical diagnostics are appended.
- The deterministic coordinator suite verifies the canonical 2/4/8-second retry schedule, acknowledgement after handler/DLQ success only, and interrupted backoff leaving the source unacknowledged.

### Go

- Every one of the nine frozen fixture frames is decoded, published, consumed, and compared through the live Kafka/Registry path.
- A retryable live handler fails three times, succeeds on attempt four, and a following barrier proves processing completed before later consumption.
- A deliberate first raw-DLQ failure returns before source commit. A same-group replacement redelivers the source; the actual `.DLQ` observer proves the source key, complete frame, and ordered original headers are unchanged, with exactly four canonical diagnostics appended.
- A cancelled in-flight handler is not committed; a same-group replacement redelivers the same source record.

Broker offsets are dynamically allocated and test-isolated by unique consumer groups and keys. The proof asserts no source commit before success/confirmed DLQ and observes same-group redelivery rather than persisting runtime keys, headers, frames, or dynamic offsets. This preserves the evidence rule against recording raw runtime material.
